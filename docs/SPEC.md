# SPEC — 기능 명세

사용자(제작자 본인)가 서울대 로스쿨 면접을 기출 제시문으로 연습하는 정적 사이트. 아래가 전체 요구사항이며, "현재"는 샘플 코드가 이미 하는 것, "예정"은 `BUILD_PLAN.md`의 항목이다.

## 0. 공통

- 사이트 이름: **법학전문대학원 입시대비** (앱바 브랜드, `<title>` 접미).
- 화면: 홈(`index.html`) · 모의면접(`practice.html`) · 기출DB(`db.html`) · 모의고사(`mock.html`) · 서가(`library.html`). 앱바 순서도 이와 같다.
- 반응형: PC(1280) · 태블릿(980 이하에서 1열) · 모바일(400). 가로 스크롤 금지.
- 글자 크기 4단계(14/16/18/20px, `html[data-font]`), 테마(시스템/밝게/어둡게, `html[data-theme]`), 블루라이트 차단(없음/하/중/상, 노란 오버레이 `mix-blend-mode: multiply`, 불투명도 .10/.20/.32). 기본값: 시스템 테마, 차단 없음, 보통 크기.
- 설정 서랍(톱니): 화면 / API 키(Claude·ChatGPT 저장·지우기) / AI 면접관(제공사·기본 모델·effort) / AI 면접해설(제공사·기본 모델·effort) / 모의면접 기본값(답변 방식, 흐름, 전사, TTS, 시간, 노크) / 초기화. 키는 공유하고 두 역할의 모델·effort는 독립적으로 저장한다. 기존 사용자는 처음에 면접관 설정을 해설 설정으로 이어받는다.
- AI 모델마다 effort 슬라이더와 현재 강도를 표시한다. 지원 단계만 선택하며 직접 입력한 미확인 모델은 비활성·모델 기본값으로 표시한다. 설정 서랍의 강도는 제공사별 기본값으로 저장한다.
- 면접 기록 서랍(앱바 톱니 왼쪽 아이콘, 모든 화면): 오른쪽 서랍에서 저장된 모의면접 목록(최신순: 날짜·시각, 세트, 복기본·모드, 질문 수·답변 방식·녹음·피드백 수, '중단'·'녹음만')을 보고, 누르면 같은 서랍이 상세로 바뀐다. 상세: 머리(시각·모드·답변 방식, 세트, 칩, [같은 세트로 모의면접] [기출DB에서 보기] [기록 삭제]), AI 피드백(§2.2 종료와 같은 영역), 문답 기록, 메모, 녹음(재생·내려받기·삭제). [목록]으로 돌아가고 [닫기]·Esc·바깥 클릭으로 닫는다. 기록을 지우면 녹음도 지운다. 서랍은 해시를 쓰지 않고, 세트 데이터나 AI 클라이언트가 없는 화면(홈·모의고사·서가)은 상세를 열 때 없는 것을 불러온다.
- 저장 위치(모두 브라우저):

| 항목 | 키 | 형식 |
|---|---|---|
| 설정 | `localStorage["snu-iv-settings-v1"]` | `app.js` DEFAULTS와 같은 키의 JSON |
| 녹음 | IndexedDB `snu-interview`(v2) / store `recordings` (keyPath `id`) | `{id, sessionId, setId, setLabel, modeLabel, question, createdAt, duration, mime, blob, filename}` |
| 면접 기록 | IndexedDB `snu-interview`(v2) / store `sessions` (keyPath `id` = 녹음의 `sessionId`) | 세트·복기본·모드·시간표·옵션·면접관 모델·문답·메모·종료 시각·AI 피드백 목록(`DATA.md` §4) |
| 기출DB 문답 | `localStorage["snu-db-threads-v1"]` | `{ [setId]: { [questionKey]: [{role:"user"|"ai", text, followup?, model?, at}] } }` |
| 기출DB AI 학습 결과 | `localStorage["snu-db-study-v1"]` | 세트·복기본별 예시답변·제시문 해설·녹음본 피드백 결과 목록(생성할 때마다 쌓임), 생성 모델·effort·시각. 녹음본 피드백은 평가한 문답 글(세트마다 한 번)·원문 구간·후속 질문 스레드도 함께 둔다(녹음 파일은 저장하지 않는다. `DATA.md` §4) |
| 서가 진도 | `localStorage["snu-library-progress-v1"]` | `{ [bookId]: 0..3 }` |

- API 키: `localStorage`에만. 저장소·코드·로그에 넣지 않는다. 설정 서랍에 [저장]/[지우기]와 "이 브라우저에 저장됨" 상태 표시.

## 1. 홈

- 히어로: 사이트 이름, 한 줄 요약, 네 화면 버튼(모의면접·기출DB·모의고사·서가), 서울대·고려대 시간표 띠 둘(학교 `format.timeline`, 정적 `plan` 상태, 넓은 화면은 나란히·좁은 화면은 위아래). 캡션은 학교·학년도와 한 줄(고려대는 기조발언 분, 서울대는 '종료 1분 전 노크').
- 네 화면 소개(열 구분선, 4열 · 760 이하 1열), 수록 기출 세트: 학교 토글(모의면접과 같은 모양, 늘 서울대로 열림, 세트 없는 학교는 흐리게 + "복기 추가 예정") → 연도별 세트 행(클릭 → `practice.html?set=<id>` → 모드 선택 단계), 서울대·고려대 진행 방식(학교마다 한 구역, `format.year` 복기 `format.basics`/`details`), 현재 설정 요약.

## 2. 모의면접

### 2.1 설정 3단계(한 화면, 번호 붙은 단계)

1. **세트**: 학교 토글(서울대 먼저, 세트 수 표시; 세트 없는 학교는 흐리게 + "복기 추가 예정") → 세트 행(연도·전형, 이름·세션, 주제, 제시문 수·복기 질문 수·트리 유무). 클릭하면 2단계로 내려가며 스크롤.
2. **모드**: `timed` 1-A 면접시간 AI 면접관 / `endless` 1-B 무한시간 AI 면접관 / `all` 2 무한시간 모든 질문 답변. 클릭하면 3단계.
3. **옵션과 시작**: 옵션 패널 + [시작] 버튼이 함께 나타난다.
   - 답변: 답변 방식(음성/텍스트), 전사(음성일 때: 브라우저 음성 인식/직접 입력), 질문 음성 읽기.
   - 시간표: 준비·대기·면접(분), 대기 여부, 노크(timed). 시간표 띠가 즉시 반영.
   - 세트 시간표(학교 `format.timeline`에 `keynote`가 있는 학교 = 고려대): 그 세트의 책 값으로 시작한다(준비 `format.prep`, 면접 `format.duration`, 대기 = 학교 `wait`(0이면 꺼짐), 기조발언 = `format.keynote`, 없으면 학교 `timeline.keynote`). 여기서 고친 시간은 세션 상태에만 두고 설정에 저장하지 않는다. 그 세트를 고르고 있는 동안([같은 세트 다시] 포함) 유지하고, 다른 세트를 고르면 그 세트의 기본값으로 돌아간다(복기본만 바꾸면 같은 세트). 캡션 오른쪽은 책 값("고려대 2023 복기 15·13 · 기조발언 7", 그해 기조발언이 책에 없으면 "기조발언 6(2026 기준)"). 그 밖의 학교는 설정값.
   - 기조발언 시간 제한(1-A이고 실효 복기본에 문제지 문항이 있는 세트만): 스위치 + 기조발언 n분(1 이상, 면접 시간 미만, 꺼지면 비활성). 기본은 세트 시간표 학교만 켜짐, 그 밖은 꺼짐이고 켜면 면접 시간의 절반. 세션 상태이며 세트를 바꾸면 기본값. 켜지면 캡션 왼쪽 "면접 13분(기조발언 7분)"과 도움말 "30초 넘기면 면접관이 끊을 수 있다."
   - AI 면접관(AI 모드만): 난이도(하/중/상/최상), 변형도(하/중/상), 흐름(사전 결정 트리/실시간 생성).
   - AI 모델(AI 모드만): 제공사 seg + 모델 select(표시명; "직접 입력…" 옵션) + effort 슬라이더. **기본값은 설정 서랍의 값**이고 여기서 바꾼 값은 이 세션에만 쓴다. [기본값으로 저장]으로 모델·effort를 설정에 반영. 키 상태 칩.
   - AI 입력 미리 보기(details): 첫 질문 생성 호출의 system/user 전문. 기조발언 제한이 켜져 있으면 첫 호출은 기조발언 뒤이므로 자리표시 답변이 든 기조발언 문답 하나와 남은 시간(면접 − 기조발언)을 넣어 보인다.
   - 답변 방식·전사·TTS·시간·난이도·변형도·흐름은 바꾸는 즉시 설정에 저장(= 다음 세션 기본값). 세트 시간표의 시간과 기조발언 제한은 저장하지 않는다. 이전 단계 요약은 단계 머리에 표시되고 [바꾸기]로 되돌아간다.
   - `?set=<id>`로 들어오면 1단계를 건너뛰고 2단계부터.

### 2.2 세션

```
준비(prep) ──▶ 대기(wait, 옵션) ──▶ 면접(interview) ──▶ 종료(done)
```

- **진행 바**(sticky): 단계명 + 남은 시간(무제한이면 경과 시간) + 시간표 띠(지난 단계 채움, 현재 단계 진행 채움, 남은 1분은 붉은색) + 동작 버튼. 모바일에서는 띠가 둘째 줄.
- **준비**: 왼쪽 제시문(지시문 + 제시문 카드, 명조), 오른쪽 열(안내 카드 + 메모)은 **진행 바 아래에 sticky**(스크롤해도 따라온다, 열 안에서 스크롤). 메모 자동 저장(세션 상태). [준비 마침 → 대기/면접], [그만두기].
- **대기**: 제시문 숨김. 큰 시계 + "메모만 들고 들어간다" + 메모(편집 가능). [입실 → 면접].
- **면접**: 제시문 다시 표시(실제로 면접실에 비치됨). 오른쪽 sticky 열: 질문 카드 → 진행 목록 → 메모.
  - 질문 카드: 번호·출처(결정 트리/AI 면접관/학생 X Q n), 질문(명조), 답변 영역, 동작 버튼(같은 줄 같은 크기).
  - **음성**: [답변 시작] → 녹음(레벨 미터, 경과 시간) + 음성 인식 실시간 표시 → [답변 완료] → 녹음을 IndexedDB에 저장, 전사 수정 가능 → [다음 질문]. 전사 '직접 입력'이면 textarea에 요지를 적는다. [답변 없이 넘기기] 가능.
  - **텍스트**: textarea("답변을 작성하시오.") → [제출 → 다음 질문] / [넘기기] / [질문 듣기]. 녹음·마이크 없음.
  - 시간: `timed`는 면접 시간 종료 시 녹음 중이면 멈추고 자동 종료. 종료 1분 전 노크 소리 + 표시(옵션). 모든 단계 전환에 신호음.
  - **기조발언**(제한이 켜진 `timed`, 문제지 문항 있는 세트): 첫 질문은 AI를 부르지 않는 고정 질문 "문제에 대한 답변을 시작하십시오."(묶음 `기조발언`. 문항은 왼쪽 지시문 상자). 질문 카드 머리에 "기조발언 경과 / 제한" 칩(넘기면 `.chip.warn`). 시계는 음성은 [답변 시작]부터(다시 답변하면 처음부터), 텍스트는 질문이 뜬 때부터, 답변을 끝내면 멈춘다. `제한 + 30초`에 아직 답변 중(음성 녹음 중 / 텍스트 미제출)이면 끊기 판정을 하고 그 뒤 30초마다 다시 한다(`AI.md` §3.1.1: AI가 정한 확률 또는 시간만의 25·50·75·100%). 끊으면 신호음, 음성은 녹음을 멈춰 저장하고 텍스트는 적힌 데까지 답변으로 확정한 뒤 곧바로 다음 질문으로 넘어가고, 다음 질문 카드에 `.callout.warn` "기조발언 8:04 — 면접관이 끊음[: 끊는 말]". 스스로 끝내면 평소처럼 다음 질문. 면접 시간이 끝나면 기조발언 중이어도 종료. 진행 목록·종료 화면·기록 서랍의 문답 시간 칸에 끊긴 답변은 "끊김", 텍스트 기조발언은 경과 시간. 제한이 꺼져 있거나 다른 모드·문항 없는 세트는 이전과 같다.
  - 모바일: 제시문 / 면접 / 메모 탭.
- **종료**: 요약 칩, [같은 세트 다시] [다른 세트] [기출DB에서 보기] [기록 보기](기록 서랍의 이 세션), AI 피드백, 이번 세션 녹음(재생·내려받기·삭제), 문답 기록(질문 + 전사/텍스트), 메모, 이 세트의 복기 질문 전체.
  - **AI 피드백**: 피드백 모델 바(제공사 seg + 모델 select + effort + 키 칩, 기본값은 설정의 **AI 면접해설**, 바꾼 값은 이 영역의 요청에만) → [피드백 받기] → `review`(`AI.md` §3.4): 총평·잘한 점·보완할 점·다음 연습 + 질문마다 검토·보완 방향. 'AI 입력 보기'로 전문 확인. 여러 번 받으면 `n차 · 모델 · effort · 시각` 블록으로 쌓이고(최신만 펼침, 이전은 접힘, 블록마다 삭제) 세션 기록에 저장된다. 키가 없거나 답변 텍스트가 하나도 없으면 버튼 비활성. 생성 중 중복 요청을 막고, 다른 기록으로 옮겨도 결과는 요청한 기록에만 저장한다.
- **세션 기록**: 텍스트·음성 모두 답변을 제출할 때마다 IndexedDB `sessions`에 저장한다(문답·메모·옵션·면접관 모델, 기조발언 제한·경과·끊김. 첫 답변 뒤의 메모 수정은 1초 뒤). 종료 때 종료 시각을 남긴다. 면접 중 탭을 닫으면 그때까지의 문답이 '중단' 기록으로 남는다. 문답·메모가 하나도 없으면 저장하지 않는다.
- 세션 중 페이지 이탈 경고(`beforeunload`), 화면 꺼짐 방지(`wakeLock`).

### 2.3 다음 질문 결정 (AI 모드)

1. `all` 모드: 복기 질문 은행을 학생 A → B → … 공통 순으로 전부.
2. 흐름 `tree`이고 세트에 `tree`가 있으면 트리를 걷는다. 분기 노드에서는 `classify`(경량: 답변 전사 + 분기 조건만)로 가지 선택; 키 없으면 사용자가 가지를 고른다. 트리 끝 → 키 있으면 실시간 생성, 없으면 질문 은행.
3. 흐름 `live` 또는 트리 없음: `nextQuestion`(제시문 전문 + 복기 질문 전체 + 지금까지의 문답 + 난이도·변형도 지침) → `{question, focus, why}`.
4. 키 없음·호출 실패: 질문 은행(중복 제거)으로 대체하고 오류를 카드에 표시.
5. 기조발언 제한(§2.2): 첫 질문은 고정 기조발언 요청이고 그 뒤에 위 순서를 따른다. AI는 기조발언 문답을 history 첫 항목(제한·실제 시간·끊김 주석)으로 받는다. 질문 은행은 문제지 문항("문제" 묶음)을 건너뛰고, 은행이 비면 면접을 마친다(추가질문 복기가 없는 고려대 2019).

실시간 질문은 실제 답변의 근거·조건을 보존해 한 논점씩 검증한다. 유한 시간에는 남은 시간과 미검증 쟁점을 고려하고, 무한 시간에는 새 검증이 가능한 동안 깊이 추궁한다. 조건의 비판적 재해석도 근거와 설명력으로 검토한다. 질문은 대체로 1~2문장, 최대 5문장이며 구두점 기준 초과 검사는 한 번 재생성 후 실패 경로로 넘긴다(변형도 하의 실제 복기 원문은 보존).

### 2.4 지난 면접

설정 화면 하단. 최근 면접 기록 5개(면접 기록 서랍과 같은 행) + [전체 기록]. 행을 누르면 기록 서랍에서 그 기록의 상세(문답·메모·녹음·AI 피드백)가 열린다. 녹음은 세션별로 묶여 상세에서 재생·내려받기·삭제한다. 세션 기록이 없는 이전 녹음은 '녹음만' 기록으로 묶인다. (예정) zip 일괄 내려받기, 전사 붙이기.

## 3. 기출DB

- 학교 토글 → 왼쪽(sticky) 세트 목록(+ 문답 수) + 학교 진행 방식(fold) / 오른쪽 세트 상세.
- 목록 위 왼쪽 [주제 가리기/보이기], 오른쪽 [최신순/과거순]. 목록·상세 주제를 함께 가리고 두 설정은 브라우저에 저장한다. 정렬해도 현재 세트와 해시는 유지한다.
- 세트 상세: 머리(학교·연도·세션·전형, 이름, 주제 칩, [이 세트로 모의면접]), AI 바(제공사 seg, 모델 select, 키 칩 — 기본값은 설정, 이 화면에서만 바뀜), 제시문 fold(기본 펼침), 복기 추가질문(학생별·공통 그룹).
- 질문 행 클릭 → 스레드: 기존 문답(나/면접관 + 꼬리질문), textarea, [AI 면접관에게 보내기](키 없으면 비활성) / [기록만 남기기] / [기록 지우기], "AI 입력 보기"(system/user 전문).
- `respond` → `{feedback, followup}`; 꼬리질문에 이어서 답할 수 있다. 문답은 localStorage에 즉시 저장.
- AI 바의 effort도 해당 화면에만 적용한다. 모델·effort·표시 설정을 바꿔도 같은 세트·복기본에서 작성 중인 답변을 유지한다.
- 질문 오른쪽 [예시답변]: 각각 독립적으로 완결된 예시 2종과 의의·유의점을 생성한다. 모든 유형에서 조건·개념·전제의 참신하고 비판적인 해석을 우선 탐색하되 원문 근거·논리적 정합성·질문에 대한 직접 답변을 갖춰야 한다. 딜레마 해소에 한정하지 않으며 조건 회피용 절충은 배제한다. 양자택일은 원칙적으로 다른 선택을, 사례 질문은 서로 다른 사례를 든다(정합적인 딜레마 해소·옹호 불가능한 선택지·특정 사례 지정은 `AI.md` §3.5). 질문 본문을 누르면 기존 문답을 펼친다.
- 제시문 아래 [제시문 해설]: 제시문 전문·문제지 문항·추가질문 전체·출전 표기를 입력해 종합 해석, 제시문별 요약·출제의도·핵심요소·참고사항, 질문별 접근, 출전 검토, 실제 서가의 연관 도서 링크를 생성한다. 출전 확인과 추정을 구분하며 외부 검색을 수행했다고 표현하지 않는다.
- 위 두 기능은 설정의 **AI 면접해설**을 기본값으로 사용한다. AI 면접관 바 아래 별도의 **AI 면접해설** 바(제공사·모델·effort·키 상태)를 두며 여기서 바꾼 값은 이 페이지의 생성·재생성에만 적용한다. 면접관 선택과 저장된 기본 설정은 바꾸지 않는다. 선택 변경만으로 API를 호출하지 않으며 기존 결과는 그대로 남긴다.
- 결과는 쌓인다: [다시 생성]마다 새 결과가 위에 붙고, 결과마다 접는 블록(`n차 · 모델 · effort · 시각`)으로 보인다. 처음 열면 최신만 펼치고, 이전 결과를 함께 펼쳐 비교할 수 있으며 다시 그려도 펼친 상태를 유지한다. 결과마다 [삭제](확인 후). [예시답변]·[제시문 해설] 버튼은 저장된 결과가 있으면 열고 닫기만 한다.
- 검증된 결과는 문답과 별도로 저장해 다시 열 때 재사용한다. 세트·복기본·제시문·문항·출전이 달라지면 이전 결과는 지우지 않고 '이전 원문'으로 표시하며, 새 입력의 결과는 [다시 생성]으로 받는다(API를 저절로 부르지 않는다). 해설은 서가 자료 변경도 반영한다. 중복 클릭은 호출 하나로 합치고, 생성 중 다른 세트로 이동해도 응답을 원래 세트에만 반영한다. 실패한 재생성은 이전 결과를 보존한다. 여러 탭에서 쌓아도 서로 덮지 않는다. 저장 공간이 부족하면 한 줄 경고(그 결과는 이 화면에만 남는다).
- 제시문 해설 아래 [녹음본 피드백]: 이 세트로 치른 모의면접의 녹음이나 문답 텍스트를 올려 평가를 받는다. 패널은 [파일 선택](여러 개) · 첨부 목록(이름·크기·문답/녹음/전사됨·전사 모델, 전사 전 녹음은 [빼기]) · [비우기], 문답 칸, [피드백 받기], 문답 칸의 [복사]·[내려받기](.txt), "AI 입력 보기". 녹음은 flac·mp3·mp4·mpeg·mpga·m4a·ogg·wav·webm(25MB 이하), 문답 텍스트는 .txt·.md·.json(1MB 이하)을 받고 그 밖은 한 줄 오류로 알린다. 텍스트 파일은 고르는 즉시 문답 칸에 들어가고(UTF-8 → EUC-KR, UTF-16은 BOM으로 판별. 세션 기록 `history[{q, a}]`·전사 `items[{question, text}]` JSON은 `Q1/A1`로 편다) 직접 붙여 넣거나 고칠 수 있다. **평가는 항상 문답 칸의 글로 한다**(6만 자 이하. 넘으면 자르지 않고 오류).
- 녹음을 첨부하면 **전사(OpenAI)** 줄(전사 모델 select · [전사])이 나타난다. 녹음은 [전사]나 [피드백 받기]를 누를 때만 OpenAI 전사 API로 보내고(파일을 고르는 것만으로는 보내지 않는다) 전사 뒤 버린다. 여러 녹음은 파일 이름 자연 정렬 순서로 전사해 `[녹음 n: 파일명]` 줄과 함께 문답 칸에 붙인다. OpenAI 키가 없으면 전사할 수 없다(한 줄 표시 + [설정]). 전사하지 않은 녹음이 남아 있으면 [피드백 받기]도 비활성이며, [빼기]로 그 녹음을 빼면 글만으로 받을 수 있다. 고른 전사 모델은 설정 `transcriptionModel`에 저장한다. 전사는 글만 받는다(목록의 전사 모델은 구간 시각을 주지 않는다). 녹음 길이는 이 사이트의 webm 녹음에서 읽히지 않아 보이지 않는다.
- [피드백 받기]는 전사하지 않은 녹음을 먼저 전사한 뒤 **AI 면접관 바의 모델**(AI 면접해설 바가 아니다)로 평가한다(`AI.md` §3.7). 결과는 (i) 문제 분석(쟁점, 제시문별 요약·짚을 논점, 문제의 요구) → (ii) 답변 평가(종합·잘한 점·부족한 점, 이어서 '문답별 평가') → (iii) 개선 방안 → 고민해볼 추가질문 → (iv) 추천 도서(실제 서가 제목·링크) → 접힌 '평가한 문답' → 후속 질문 순으로 보인다. 평가의 중심은 **면접관이 실제로 한 질문마다 제대로 답했는가**이고(복기된 추가질문은 참고 자료일 뿐 이 면접의 질문이 아니다), 1차 기준은 제시문과 문제이며 제시문 밖 법학 지식의 유무로 평가하지 않는다.
- 문답 칸의 글에 Q/A·화자 표시가 없어도 된다. 녹음 전사처럼 질문과 답변이 표시 없이 이어진 글은 평가 모델이 스스로 면접관의 질문과 지원자의 답변을 가른다. 문제지 문항이 있는 세트(서울대 밖의 학교)는 지원자가 질문 없이 문항에 차례로 답하는 **기조답변**으로 시작하고 추가질문이 그 답변에서 이어지는 흐름으로 읽는다: 기조답변은 문항마다 문답 하나(`[문제 1] …`)로 가르고, 추가질문의 답변은 기조답변의 입장을 지켰는지·고쳤는지와 함께 평가한다.
- **고민해볼 추가질문**은 면접관이 그 답변들을 듣고 더 물을 수 있었던 질문이다(질문과 그 질문이 나온 발언·겨누는 점 한 줄). 기록에서 이미 물은 질문과 복기 추가질문은 빼고, 중요하고 어려운 것만 중요한 순서로 20개 이내.
- 올린 문답이 **다른 세트의 면접**이거나 면접 문답이 아니면 평가하지 않고 "이 세트의 문답을 찾지 못했다."와 모델이 적은 까닭 한 문장(기록이 다루는 제시문이 이 세트와 어떻게 다른지)을 보인다. 학년도와 시행 연도가 달라(2021년에 치른 시험은 2022학년도) 세트를 잘못 고르기 쉽다.
- **문답별 평가**는 AI가 가른 문답의 접는 목록(`Q1. 질문`, 추정한 질문은 "(추정)")이다. 하나를 펼치면 그 문답의 **원문**(평가한 문답에서 그 문답이 차지하는 구간), 답변 요지, 평가, 개선이 함께 보인다. 원문 구간은 평가 모델이 낸 기록 단위 번호(⟦n⟧) 범위를 저장할 때 글자 위치로 바꾼 것이며, 범위가 맞지 않으면 '위치 없음'(목록 머리에 개수). **평가한 문답**은 평가에 보낸 문답 칸의 글 전문을 구간마다 `Q n`·'문답 밖' 머리를 달아 보이고(첨부 이름·전사 모델 한 줄), [복사](전문)·[내려받기](.md: 평가 전체·문답별 원문·전문·후속 질문)를 둔다. 결과에 저장되므로 다시 열어도 보인다.
- **후속 질문**: 결과마다 스레드(나 / 면접관 · 모델 말풍선), 질문 칸("피드백에 대해 묻거나 반박하시오."), [질문하기]·[후속 질문 지우기], "AI 입력 보기". AI 면접관 바의 모델이 제시문 전문·평가한 문답·그 피드백·앞선 후속 문답을 근거로 답한다(`AI.md` §3.7). 질문은 먼저 저장되고, 답이 오지 않으면 버튼이 [다시 묻기]가 되어 같은 질문에 다시 답을 받는다. 답을 기다리는 동안 그 결과의 [질문하기]·[후속 질문 지우기]·[삭제]는 막힌다. 스레드는 결과와 함께 저장되고 결과를 지우면 함께 지워진다. 원문이 바뀐 결과('이전 원문')에는 묻지 않는다. 질문은 2,000자 이하. (다음 단계: 문답별로 고친 답변을 다시 평가받기 — 지금은 후속 질문으로 "이렇게 고쳐 답하면?"을 물을 수 있다.)
- 녹음본 피드백 결과도 같은 방식으로 쌓인다(n차, 최신만 펼침, 결과마다 삭제, 원문이 바뀐 결과는 '이전 원문'). 받을 때마다 새 결과다(재사용 없음). 문답 칸과 첨부는 세트·복기본별로 이 화면에만 두며(새로 고침하면 사라진다) 설정 변경으로 다시 그려도 유지한다. 요청 중 다른 세트로 옮겨도 전사와 결과는 요청한 세트·복기본에만 남는다. 실패하면 한 줄 오류와 함께 문답 칸·첨부를 그대로 둔다. 텍스트 파일을 읽는 동안에는 폼을 잠근다. 6만 자를 넘는 문답은 녹음을 보내기 전에 멈춘다. 평가 모델의 키가 없으면 [피드백 받기]·[질문하기]만 비활성이고 파일 읽기·문답 칸·전문 보기·문답별 원문 대조·복사·내려받기는 동작한다.
- 면접관 응답의 진행·오류도 세트·복기본·질문별로 관리한다. 응답 대기 중 탐색은 즉시 화면에 반영하고, 늦은 응답은 원래 문답에만 저장한다. 같은 질문에 중복 전송하거나 진행 중 기록을 지울 수 없다.
- 해시 `#<setId>`로 세트를 연다. (예정) 스레드 내보내기, 검색·필터, 모의면접 문답 기록과 연결.

## 4. 모의고사

학교별 실전 모의고사의 진행 조건·지시문·제시문·문항·추가질문을 본다(`mock.html`, `assets/mock.js`, 데이터 `DATA.md` §6). 홈의 화면 소개에 모의고사 카드가 있다(네 화면, 4열 · 760 이하 1열).

- 머리 아래 자리 탭 둘: **2027 고려대 AI 모의고사** · **김종수 모의고사**(학교 토글과 같은 모양, 문제 수 표시, 문제 없는 자리는 흐리게). 자리 하나 = 묶음(`MOCK_DB.series`) 하나이고 묶음이 늘면 탭이 하나씩 는다.
- 2027 고려대 AI 모의고사: 사용자가 AI로 출제한 2027학년도 고려대 예상 문항. 목록·상세는 김종수 모의고사와 같고 두 자리만 다르다. 세트 행의 학교 약칭 자리에 난이도 별 다섯 개(`★★★★☆`, 고려대 평균 = ★2. 읽기 프로그램에는 '난이도 4/5'), 문제 번호 자리에 분야 넘버링(`인문 A`, `법학·과학기술 B`. 분야는 법학·인문·사회·경제·과학기술 중 1~2개). 상세 이름은 `고려대 인문 A`, 머리 줄 끝에 난이도 별.
- 두 자리 모두 기출DB와 같은 배치(왼쪽 sticky 목록, 오른쪽 상세, 좁은 화면 1열). 목록이 화면보다 길면 목록 열 안에서 스크롤한다(다시 그려도 스크롤 자리 유지, 해시로 연 문제의 행은 열 안에 보이게). 목록은 학교 순서(서울대 → 고려대 → 연세대 → 성균관대 → 한양대 → 서강대 → 중앙대 → 경희대 → 한국외대 → 이화여대)로 이어지며 연도로 묶지 않는다. 세트 행: 학교 약칭(기출DB의 연도 자리), 문제 번호, 주제, 제시문·문항(·추가질문) 수, 준비·면접(·기조발언) 시간.
- 목록 위 [주제 가리기/보이기]: 기출DB와 같은 설정(`dbHideThemes`)이라 두 화면이 함께 바뀐다. 목록·상세 주제를 함께 가린다.
- 상세: 머리(묶음 · 학교 · 문제 번호, 이름 `서울대 184`, 주제 칩, 교재·쪽), 진행 조건(시간표 띠 준비 → 면접 + 책의 진행 조건 줄), 제시문 fold(기본 펼침: 지시문 상자 + 제시문 카드, 머리 `AIClient.passageHead`), 문항 fold(기본 접힘: 준비 시간에 문제를 미리 보지 않는 학교가 있다. `Q1`…), 추가질문 fold(책에 추가질문이 있는 문제만, 기본 접힘: 면접관이 기조답변 뒤에 묻는 질문. 번호는 문항 뒤로 이어진다 — 문항 3개면 `Q4`부터). 펼침·접힘은 다시 그려도 유지한다.
- 해시 `#<문제 id>`로 문제를, `#<묶음 id>`(`#ai`·`#kim`)로 자리를 연다. 해시가 없으면 문제가 있는 첫 자리의 첫 문제. 문제가 없는 자리는 "<자리 이름> — 추가 예정" 한 줄.
- (예정) 브라우저에서 만드는 AI 맞춤 모의고사(P4-8), 문제별 문답 스레드·AI 예시답변·제시문 해설·녹음본 피드백·모의면접에서 치르기(P4-9).

## 5. 면접대비 서가

도서 100선 뷰어(원본 HTML에서 이식). 개요(등급 분포, 진도, 먼저 읽을 7권, 아홉 분야, 선정 기준) / 도서(검색·등급·분야·판본·정렬·진도 필터) / 쟁점(18개, 사실·축·활용·질문·90초 구술 틀) / 읽는 순서(독서 시간 계산기, 단계, 짝지어 읽기, 전체 순위). 책 상세 서랍(해시 `#b<id>`), 진도 0~3 기록. (예정) 연결 지도 SVG, 효용–비용 산점도, 읽는 범위–쟁점 그래프, 쟁점×분야 매트릭스, 진도 내보내기/가져오기.
