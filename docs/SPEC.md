# SPEC — 기능 명세

사용자(제작자 본인)가 서울대 로스쿨 면접을 기출 제시문으로 연습하는 정적 사이트. 아래가 전체 요구사항이며, "현재"는 샘플 코드가 이미 하는 것, "예정"은 `BUILD_PLAN.md`의 항목이다.

## 0. 공통

- 사이트 이름: **서울대학교 법학전문대학원 면접 및 구술고사 대비** (앱바 브랜드, `<title>` 접미).
- 화면: 홈(`index.html`) · 모의면접(`practice.html`) · 기출DB(`db.html`) · 서가(`library.html`). 앱바 순서도 이와 같다.
- 반응형: PC(1280) · 태블릿(980 이하에서 1열) · 모바일(400). 가로 스크롤 금지.
- 글자 크기 4단계(14/16/18/20px, `html[data-font]`), 테마(시스템/밝게/어둡게, `html[data-theme]`), 블루라이트 차단(없음/하/중/상, 노란 오버레이 `mix-blend-mode: multiply`, 불투명도 .10/.20/.32). 기본값: 시스템 테마, 차단 없음, 보통 크기.
- 설정 서랍(톱니): 화면 / API 키(Claude·ChatGPT 저장·지우기) / AI 면접관(제공사·기본 모델·effort) / AI 면접해설(제공사·기본 모델·effort) / 모의면접 기본값(답변 방식, 흐름, 전사, TTS, 시간, 노크) / 초기화. 키는 공유하고 두 역할의 모델·effort는 독립적으로 저장한다. 기존 사용자는 처음에 면접관 설정을 해설 설정으로 이어받는다.
- AI 모델마다 effort 슬라이더와 현재 강도를 표시한다. 지원 단계만 선택하며 직접 입력한 미확인 모델은 비활성·모델 기본값으로 표시한다. 설정 서랍의 강도는 제공사별 기본값으로 저장한다.
- 면접 기록 서랍(앱바 톱니 왼쪽 아이콘, 모든 화면): 오른쪽 서랍에서 저장된 모의면접 목록(최신순: 날짜·시각, 세트, 복기본·모드, 질문 수·답변 방식·녹음·피드백 수, '중단'·'녹음만')을 보고, 누르면 같은 서랍이 상세로 바뀐다. 상세: 머리(시각·모드·답변 방식, 세트, 칩, [같은 세트로 모의면접] [기출DB에서 보기] [기록 삭제]), AI 피드백(§2.2 종료와 같은 영역), 문답 기록, 메모, 녹음(재생·내려받기·삭제). [목록]으로 돌아가고 [닫기]·Esc·바깥 클릭으로 닫는다. 기록을 지우면 녹음도 지운다. 서랍은 해시를 쓰지 않고, 세트 데이터·AI 클라이언트가 없는 화면(홈·서가)은 상세를 열 때 불러온다.
- 저장 위치(모두 브라우저):

| 항목 | 키 | 형식 |
|---|---|---|
| 설정 | `localStorage["snu-iv-settings-v1"]` | `app.js` DEFAULTS와 같은 키의 JSON |
| 녹음 | IndexedDB `snu-interview`(v2) / store `recordings` (keyPath `id`) | `{id, sessionId, setId, setLabel, modeLabel, question, createdAt, duration, mime, blob, filename}` |
| 면접 기록 | IndexedDB `snu-interview`(v2) / store `sessions` (keyPath `id` = 녹음의 `sessionId`) | 세트·복기본·모드·시간표·옵션·면접관 모델·문답·메모·종료 시각·AI 피드백 목록(`DATA.md` §4) |
| 기출DB 문답 | `localStorage["snu-db-threads-v1"]` | `{ [setId]: { [questionKey]: [{role:"user"|"ai", text, followup?, model?, at}] } }` |
| 기출DB AI 학습 결과 | `localStorage["snu-db-study-v1"]` | 세트·복기본별 예시답변·제시문 해설 결과 목록(생성할 때마다 쌓임), 생성 모델·effort·시각(`DATA.md` §4) |
| 서가 진도 | `localStorage["snu-library-progress-v1"]` | `{ [bookId]: 0..3 }` |

- API 키: `localStorage`에만. 저장소·코드·로그에 넣지 않는다. 설정 서랍에 [저장]/[지우기]와 "이 브라우저에 저장됨" 상태 표시.

## 1. 홈

- 히어로: 사이트 이름, 한 줄 요약, 세 화면 버튼, 시간표 띠(준비 20 → 대기 5 → 면접 15, 정적 `plan` 상태).
- 세 화면 소개(열 구분선), 수록 기출 세트: 학교 토글(모의면접과 같은 모양, 늘 서울대로 열림, 세트 없는 학교는 흐리게 + "복기 추가 예정") → 연도별 세트 행(클릭 → `practice.html?set=<id>` → 모드 선택 단계), 서울대 진행 방식(2025 복기 `format.basics`/`details`), 현재 설정 요약.

## 2. 모의면접

### 2.1 설정 3단계(한 화면, 번호 붙은 단계)

1. **세트**: 학교 토글(서울대 먼저, 세트 수 표시; 세트 없는 학교는 흐리게 + "복기 추가 예정") → 세트 행(연도·전형, 이름·세션, 주제, 제시문 수·복기 질문 수·트리 유무). 클릭하면 2단계로 내려가며 스크롤.
2. **모드**: `timed` 1-A 면접시간 AI 면접관 / `endless` 1-B 무한시간 AI 면접관 / `all` 2 무한시간 모든 질문 답변. 클릭하면 3단계.
3. **옵션과 시작**: 옵션 패널 + [시작] 버튼이 함께 나타난다.
   - 답변: 답변 방식(음성/텍스트), 전사(음성일 때: 브라우저 음성 인식/직접 입력), 질문 음성 읽기.
   - 시간표: 준비·대기·면접(분), 대기 여부, 노크(timed). 시간표 띠가 즉시 반영.
   - AI 면접관(AI 모드만): 난이도(하/중/상/최상), 변형도(하/중/상), 흐름(사전 결정 트리/실시간 생성).
   - AI 모델(AI 모드만): 제공사 seg + 모델 select(표시명; "직접 입력…" 옵션) + effort 슬라이더. **기본값은 설정 서랍의 값**이고 여기서 바꾼 값은 이 세션에만 쓴다. [기본값으로 저장]으로 모델·effort를 설정에 반영. 키 상태 칩.
   - AI 입력 미리 보기(details): 첫 질문 생성 호출의 system/user 전문.
   - 답변 방식·전사·TTS·시간·난이도·변형도·흐름은 바꾸는 즉시 설정에 저장(= 다음 세션 기본값). 이전 단계 요약은 단계 머리에 표시되고 [바꾸기]로 되돌아간다.
   - `?set=<id>`로 들어오면 1단계를 건너뛰고 2단계부터.

### 2.2 세션

```
준비(prep) ──▶ 대기(wait, 옵션) ──▶ 면접(interview) ──▶ 종료(done)
```

- **진행 바**(sticky): 단계명 + 남은 시간(무제한이면 경과 시간) + 시간표 띠(지난 단계 채움, 현재 단계 진행 채움, 남은 1분은 붉은색) + 동작 버튼. 모바일에서는 띠가 둘째 줄.
- **준비**: 왼쪽 제시문(지시문 + 제시문 카드, 명조), 오른쪽 열(안내 카드 + 메모)은 **진행 바 아래에 sticky**(스크롤해도 따라온다, 열 안에서 스크롤). 메모 자동 저장(세션 상태). [준비 마침 → 대기/면접], [그만두기].
- **대기**: 제시문 숨김. 큰 시계 + "메모만 들고 들어간다" + 메모(편집 가능). [입실 → 면접].
- **면접**: 제시문 다시 표시(실제로 면접실에 비치됨). 오른쪽 sticky 열: 질문 카드 → 진행 목록 → 메모.
  - 질문 카드: 번호·출처(결정 트리/AI 면접관/학생 X Q n), 질문(명조), 답변 영역, 동작 버튼(같은 줄 같은 크기).
  - **음성**: [답변 시작] → 녹음(레벨 미터, 경과 시간) + 음성 인식 실시간 표시 → [답변 완료] → 녹음을 IndexedDB에 저장, 전사 수정 가능 → [다음 질문]. 전사 '직접 입력'이면 textarea에 요지를 적는다. [답변 없이 넘기기] 가능.
  - **텍스트**: textarea("답변을 작성하시오.") → [제출 → 다음 질문] / [넘기기] / [질문 듣기]. 녹음·마이크 없음.
  - 시간: `timed`는 면접 시간 종료 시 녹음 중이면 멈추고 자동 종료. 종료 1분 전 노크 소리 + 표시(옵션). 모든 단계 전환에 신호음.
  - 모바일: 제시문 / 면접 / 메모 탭.
- **종료**: 요약 칩, [같은 세트 다시] [다른 세트] [기출DB에서 보기] [기록 보기](기록 서랍의 이 세션), AI 피드백, 이번 세션 녹음(재생·내려받기·삭제), 문답 기록(질문 + 전사/텍스트), 메모, 이 세트의 복기 질문 전체.
  - **AI 피드백**: 피드백 모델 바(제공사 seg + 모델 select + effort + 키 칩, 기본값은 설정의 **AI 면접해설**, 바꾼 값은 이 영역의 요청에만) → [피드백 받기] → `review`(`AI.md` §3.4): 총평·잘한 점·보완할 점·다음 연습 + 질문마다 검토·보완 방향. 'AI 입력 보기'로 전문 확인. 여러 번 받으면 `n차 · 모델 · effort · 시각` 블록으로 쌓이고(최신만 펼침, 이전은 접힘, 블록마다 삭제) 세션 기록에 저장된다. 키가 없거나 답변 텍스트가 하나도 없으면 버튼 비활성. 생성 중 중복 요청을 막고, 다른 기록으로 옮겨도 결과는 요청한 기록에만 저장한다.
- **세션 기록**: 텍스트·음성 모두 답변을 제출할 때마다 IndexedDB `sessions`에 저장한다(문답·메모·옵션·면접관 모델. 첫 답변 뒤의 메모 수정은 1초 뒤). 종료 때 종료 시각을 남긴다. 면접 중 탭을 닫으면 그때까지의 문답이 '중단' 기록으로 남는다. 문답·메모가 하나도 없으면 저장하지 않는다.
- 세션 중 페이지 이탈 경고(`beforeunload`), 화면 꺼짐 방지(`wakeLock`).

### 2.3 다음 질문 결정 (AI 모드)

1. `all` 모드: 복기 질문 은행을 학생 A → B → … 공통 순으로 전부.
2. 흐름 `tree`이고 세트에 `tree`가 있으면 트리를 걷는다. 분기 노드에서는 `classify`(경량: 답변 전사 + 분기 조건만)로 가지 선택; 키 없으면 사용자가 가지를 고른다. 트리 끝 → 키 있으면 실시간 생성, 없으면 질문 은행.
3. 흐름 `live` 또는 트리 없음: `nextQuestion`(제시문 전문 + 복기 질문 전체 + 지금까지의 문답 + 난이도·변형도 지침) → `{question, focus, why}`.
4. 키 없음·호출 실패: 질문 은행(중복 제거)으로 대체하고 오류를 카드에 표시.

실시간 질문은 실제 답변의 근거·조건을 보존해 한 논점씩 검증한다. 유한 시간에는 남은 시간과 미검증 쟁점을 고려하고, 무한 시간에는 새 검증이 가능한 동안 깊이 추궁한다. 조건의 비판적 재해석도 근거와 설명력으로 검토한다. 질문은 대체로 1~2문장, 최대 5문장이며 구두점 기준 초과 검사는 한 번 재생성 후 실패 경로로 넘긴다(변형도 하의 실제 복기 원문은 보존).

### 2.4 지난 면접

설정 화면 하단. 최근 면접 기록 5개(면접 기록 서랍과 같은 행) + [전체 기록]. 행을 누르면 기록 서랍에서 그 기록의 상세(문답·메모·녹음·AI 피드백)가 열린다. 녹음은 세션별로 묶여 상세에서 재생·내려받기·삭제한다. 세션 기록이 없는 이전 녹음은 '녹음만' 기록으로 묶인다. (예정) zip 일괄 내려받기, 전사 붙이기.

## 3. 기출DB

- 학교 토글 → 왼쪽(sticky) 세트 목록(+ 문답 수) + 학교 진행 방식(fold) / 오른쪽 세트 상세.
- 목록 위 왼쪽 [주제 가리기/보이기], 오른쪽 [최신순/과거순]. 목록·상세 주제를 함께 가리고 두 설정은 브라우저에 저장한다. 정렬해도 현재 세트와 해시는 유지한다.
- 세트 상세: 머리(학교·연도·세션·전형, 이름, 주제 칩, [이 세트로 모의면접]), AI 바(제공사 seg, 모델 select, 키 칩 — 기본값은 설정, 이 화면에서만 바뀜), 제시문 fold(기본 펼침), 복기 추가질문(학생별·공통 그룹).
- 질문 행 클릭 → 스레드: 기존 문답(나/면접관 + 꼬리질문), textarea, [AI 면접관에게 보내기](키 없으면 비활성) / [기록만 남기기] / [기록 지우기], "AI 입력 보기"(system/user 전문).
- `respond` → `{feedback, followup}`; 꼬리질문에 이어서 답할 수 있다. 문답은 localStorage에 즉시 저장.
- AI 바의 effort도 해당 화면에만 적용한다. 모델·effort·표시 설정을 바꿔도 같은 세트·복기본에서 작성 중인 답변을 유지한다.
- 질문 오른쪽 [예시답변]: 각각 독립적으로 완결된 예시 2종과 의의·유의점을 생성한다. 모든 유형에서 조건·개념·전제의 참신하고 비판적인 해석을 우선 탐색하되 원문 근거·논리적 정합성·질문에 대한 직접 답변을 갖춰야 한다. 딜레마 해소에 한정하지 않으며 조건 회피용 절충은 배제한다. 양자택일은 원칙적으로 다른 선택을, 사례 질문은 서로 다른 사례를 든다(정합적인 딜레마 해소·옹호 불가능한 선택지·특정 사례 지정은 `AI.md` §3.5). 질문 본문을 누르면 기존 문답을 펼친다.
- 제시문 아래 [제시문 해설]: 제시문 전문·문제지 문항·추가질문 전체·출전 표기를 입력해 종합 해석, 제시문별 요약·출제의도·핵심요소·참고사항, 질문별 접근, 출전 검토, 실제 서가의 연관 도서 링크를 생성한다. 출전 확인과 추정을 구분하며 외부 검색을 수행했다고 표현하지 않는다.
- 위 두 기능은 설정의 **AI 면접해설**을 기본값으로 사용한다. AI 면접관 바 아래 별도의 **AI 면접해설** 바(제공사·모델·effort·키 상태)를 두며 여기서 바꾼 값은 이 페이지의 생성·재생성에만 적용한다. 면접관 선택과 저장된 기본 설정은 바꾸지 않는다. 선택 변경만으로 API를 호출하지 않으며 기존 결과는 그대로 남긴다.
- 결과는 쌓인다: [다시 생성]마다 새 결과가 위에 붙고, 결과마다 접는 블록(`n차 · 모델 · effort · 시각`)으로 보인다. 처음 열면 최신만 펼치고, 이전 결과를 함께 펼쳐 비교할 수 있으며 다시 그려도 펼친 상태를 유지한다. 결과마다 [삭제](확인 후). [예시답변]·[제시문 해설] 버튼은 저장된 결과가 있으면 열고 닫기만 한다.
- 검증된 결과는 문답과 별도로 저장해 다시 열 때 재사용한다. 세트·복기본·제시문·문항·출전이 달라지면 이전 결과는 지우지 않고 '이전 원문'으로 표시하며, 새 입력의 결과는 [다시 생성]으로 받는다(API를 저절로 부르지 않는다). 해설은 서가 자료 변경도 반영한다. 중복 클릭은 호출 하나로 합치고, 생성 중 다른 세트로 이동해도 응답을 원래 세트에만 반영한다. 실패한 재생성은 이전 결과를 보존한다. 여러 탭에서 쌓아도 서로 덮지 않는다. 저장 공간이 부족하면 한 줄 경고(그 결과는 이 화면에만 남는다).
- 면접관 응답의 진행·오류도 세트·복기본·질문별로 관리한다. 응답 대기 중 탐색은 즉시 화면에 반영하고, 늦은 응답은 원래 문답에만 저장한다. 같은 질문에 중복 전송하거나 진행 중 기록을 지울 수 없다.
- 해시 `#<setId>`로 세트를 연다. (예정) 스레드 내보내기, 검색·필터, 모의면접 문답 기록과 연결.

## 4. 면접대비 서가

도서 100선 뷰어(원본 HTML에서 이식). 개요(등급 분포, 진도, 먼저 읽을 7권, 아홉 분야, 선정 기준) / 도서(검색·등급·분야·판본·정렬·진도 필터) / 쟁점(18개, 사실·축·활용·질문·90초 구술 틀) / 읽는 순서(독서 시간 계산기, 단계, 짝지어 읽기, 전체 순위). 책 상세 서랍(해시 `#b<id>`), 진도 0~3 기록. (예정) 연결 지도 SVG, 효용–비용 산점도, 읽는 범위–쟁점 그래프, 쟁점×분야 매트릭스, 진도 내보내기/가져오기.
